> **更新日期**: 2026-02-25

## 1. 背景与目标

### 1.1 业务背景

阿里拍卖平台汇聚了大量不同类型的资产标的（房产、车辆、土地、设备、知识产权等），资产信息以**非结构化文本**为主。VIP 客户在寻找意向资产时，往往只能通过关键词搜索或人工筛选，效率低下且容易遗漏优质标的。

### 1.2 产品目标

构建一个**基于语义向量检索**的智能搜索助手，让 VIP 客户通过自然语言描述购买需求，由 AI 自动匹配最相关的拍卖资产，并以**对话式交互**呈现推理过程和推荐结果。

### 1.3 核心价值

| 价值维度 | 说明 |
|---------|------|
| **降低搜索门槛** | 用户无需了解资产分类体系，用自然语言描述即可 |
| **提升匹配精度** | 语义向量检索取代关键词匹配，理解用户意图 |
| **增强信任感** | 思维链展示让用户看到 AI 的推理过程，增强结果可信度 |
| **提升管理效率** | 管理员通过 Excel 批量导入资产，系统自动向量化 |

### 2.1 用户角色

| 角色 | 说明 | 权限 |

|------|---------|---------|

## 3. 功能需求

### 3.1 智能搜索模块（VIP 客户端）

#### 3.1.1 对话界面

- 页面顶部显示"💬 我要买"标题和提示文案
- 对话区域全屏高度，支持滚动浏览历史消息
- 底部固定输入栏，含文本输入框和发送按钮
- 支持 Enter 键快捷发送
- 发送后显示"AI 正在分析您的需求…"加载动画

#### 3.1.2 AI 响应展示

**思维链展示**（在对话气泡内逐步呈现）：

| 步骤 | 图标 | 标题 | 示例内容 |
|------|------|------|---------|
| 1 | 🔍 | 需求理解 | 正在分析您的需求:「我想买杭州的住宅」 |
| 2 | 📊 | 向量检索 | 在 15 条资产中进行语义相似度检索... |
| 3 | 📋 | 相似度匹配 | 找到 5 条匹配资产，最高相似度: 64% |
| 4 | ✅ | 结果排序 | 已按相似度从高到低排序，为您推荐以下标的 |

- 思维链各步骤以 Steps 组件逐步渐显（每步间隔 400ms）
- 当资产库为空时，思维链显示"⚠️ 资产库为空，请先导入资产数据"

**商品卡片列表**（思维链下方展示）：

- 每张卡片包含：
  - 资产标题（加粗）
  - 描述文本（最多 2 行省略）
  - 类别标签（彩色 Tag）
  - 所在地（📍 图标）
  - 起拍价（💰 红色加粗，自动格式化为"万/亿"）
  - 拍卖状态标签（正在拍卖=红色，即将开拍=蓝色）
  - 相似度环形进度条（>70% 绿色，40-70% 黄色，<40% 红色）

#### 3.1.3 消息气泡

| 类型 | 对齐 | 背景色 | 头像 |
|------|------|-------|------|
| 用户消息 | 右对齐 | 蓝色 (#1677ff) | 👤 蓝底 |
| AI 消息 | 左对齐 | 浅灰 (#f5f5f5) | 🤖 绿底 |
| 系统欢迎 | 左对齐 | 浅灰 (#f5f5f5) | 🤖 绿底 |

### 3.2 资产管理模块（管理后台）

#### 3.2.1 统计概览

- 显示资产总数统计卡片
- "导入 Excel"按钮
- "刷新"按钮

#### 3.2.2 Excel 导入

- 支持 `.xlsx` 和 `.xls` 格式
- 自动识别中文列名映射（见 §4.2 Excel 格式规范）
- 导入成功后显示"成功导入 N 条资产"提示
- 导入失败显示具体错误原因

#### 3.2.3 资产列表

- 表格列：标题、类别、所在地、起拍价、状态、操作
- 分页：每页 10 条，底部显示"共 N 条"
- 操作列：删除（带二次确认弹窗）

#### 3.2.4 自动向量化

- Excel 导入时，每条资产自动拼接「标题 + 描述 + 类别 + 所在地」作为向量化文本
- 调用 ChromaDB 嵌入模型生成向量并持久化存储
- 向量化过程对管理员透明，无需手动触发

## 4. 数据模型

### 4.1 资产 (Asset)

| 字段 | 类型 | 说明 | 必填 |
|------|------|------|------|
| `id` | string (UUID) | 资产唯一标识，导入时自动生成 | 是 |
| `title` | string | 资产标题/名称 | 是 |
| `description` | string | 资产详细描述 | 否 |
| `category` | string | 资产类别（住宅/商铺/写字楼/车辆/土地/设备/知识产权） | 否 |
| `location` | string | 资产所在城市/地区 | 否 |
| `starting_price` | float | 起拍价格（元） | 否 |
| `status` | string | 拍卖状态（即将开拍/正在拍卖/已结束） | 否 |
| `source_url` | string | 拍卖详情链接 | 否 |

### 4.2 Excel 格式规范

系统通过模糊匹配识别列名，支持以下中英文表头：

| 字段 | 可识别的列名 |
|------|------------|
| `title` | 标题、名称、资产名称、title |
| `description` | 描述、详情、资产描述、说明、description |
| `category` | 类别、分类、类型、资产类别、category |
| `location` | 所在地、地址、位置、城市、地区、location |
| `starting_price` | 起拍价、价格、起始价、底价、price |
| `status` | 状态、拍卖状态、status |
| `source_url` | 链接、url、网址、来源 |

### 4.3 对话消息 (Message)

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 消息唯一标识 |
| `role` | enum | `user` / `assistant` / `system` |
| `content` | string | 消息文本内容 |
| `thinking` | ThinkingStep[] | AI 思维链步骤（仅 assistant） |
| `matches` | AssetMatch[] | 匹配的资产列表（仅 assistant） |

### 4.4 思维链步骤 (ThinkingStep)

| 字段 | 类型 | 说明 |
|------|------|------|
| `step` | string | 步骤名称（需求理解/向量检索/相似度匹配/结果排序） |
| `detail` | string | 步骤详情描述 |
| `icon` | string | 步骤图标（emoji） |

### 4.5 资产匹配结果 (AssetMatch)

| 字段 | 类型 | 说明 |
|------|------|------|
| `asset` | Asset | 匹配到的资产对象 |
| `score` | float | 相似度评分（0~1） |
| `reason` | string | 匹配原因摘要 |

## 5. API 设计

### 5.1 资产管理 API

#### `POST /api/assets/upload` — 上传 Excel 导入资产

- **请求**: `multipart/form-data`，字段 `file`（.xlsx/.xls 文件）
- **成功响应**: `200 { "message": "成功导入 N 条资产", "count": N }`
- **错误响应**: `400 { "detail": "错误原因" }`

#### `GET /api/assets` — 获取资产列表（分页）

- **查询参数**: `page`（默认 1）、`page_size`（默认 20，最大 100）
- **响应**: `200 { "assets": [...], "total": N, "page": P, "page_size": S }`

#### `DELETE /api/assets/{id}` — 删除单条资产

- **响应**: `200 { "message": "删除成功" }`

#### `POST /api/assets/batch-delete` — 批量删除

- **请求体**: `["id1", "id2", ...]`
- **响应**: `200 { "message": "成功删除 N 条资产" }`

#### `GET /api/assets/stats` — 资产统计

- **响应**: `200 { "total_assets": N }`

### 5.2 智能搜索 API

#### `POST /api/chat` — 对话搜索

- **请求体**: `{ "content": "用户需求文本" }`
- **响应**:

```json
{
  "thinking": [
    { "step": "需求理解", "detail": "正在分析...", "icon": "🔍" },
    { "step": "向量检索", "detail": "在 N 条资产中检索...", "icon": "📊" },
    { "step": "相似度匹配", "detail": "找到 M 条匹配资产...", "icon": "📋" },
    { "step": "结果排序", "detail": "已按相似度排序...", "icon": "✅" }
  ],
  "matches": [
    {
      "asset": { "id": "...", "title": "...", ... },
      "score": 0.85,
      "reason": "类别: 住宅 | 位置: 杭州 | 起拍价: ¥350万 | 匹配度: 85%"
    }
  ],
  "summary": "根据您的需求，为您找到 M 条匹配的拍卖资产"
}
```

#### `GET /api/health` — 健康检查

- **响应**: `200 { "status": "ok" }`

## 9. 非功能需求

### 9.1 性能

| 指标 | 目标 |
|------|------|
| 对话搜索响应时间 | < 3 秒（含向量检索） |
| Excel 导入速度 | 100 条/秒 |
| 前端首屏加载 | < 2 秒 |
| 思维链动画流畅性 | 每步 400ms 渐显，无卡顿 |

### 9.2 可靠性

- ChromaDB 数据本地持久化，服务重启不丢失
- API 错误统一返回结构化错误信息
- 前端网络错误友好提示

### 9.3 可扩展性

- 嵌入模型可配置（通过环境变量 `EMBEDDING_MODEL`）
- 检索结果数量可配置（通过环境变量 `TOP_K`，默认 5）
- ChromaDB 存储路径可配置（通过环境变量 `CHROMA_PERSIST_DIR`）
- Excel 列名映射可扩展

### 9.4 兼容性

- 前端支持 Chrome/Edge/Firefox 最新版本
- 响应式布局适配桌面端

## 10. 已知局限与后续迭代

### 10.1 当前版本局限

| 局限 | 说明 | 建议迭代方向 |
|------|------|------------|
| 嵌入模型 | 默认英文模型对中文语义理解有限 | 替换为中文专用模型（如 `BAAI/bge-small-zh-v1.5`） |
| 无 LLM 集成 | 思维链为结构化模板，非真正 AI 推理 | 接入 LLM（如通义千问）实现自然语言推理和多轮对话 |
| 无权限控制 | 前后端无登录鉴权 | 增加用户登录和角色权限 |
| 无图片展示 | 资产卡片无图片 | Excel 中增加图片 URL 列，卡片显示缩略图 |
| 单机部署 | ChromaDB 本地文件存储 | 迁移到 ChromaDB Server 或 Milvus 分布式方案 |

### 10.2 V2 迭代规划

1. **接入 LLM**: 集成通义千问/ChatGLM，实现真正的 AI 推理和多轮对话
2. **中文嵌入优化**: 替换为 BGE 中文嵌入模型
3. **资产详情页**: 点击卡片跳转详情页或打开侧边栏
4. **收藏与对比**: 用户可收藏资产并进行多资产对比
5. **管理员数据看板**: 搜索热词统计、匹配率分析
